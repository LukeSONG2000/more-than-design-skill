# 每日更新检查

更新检查在 skill 被加载时触发，不是后台定时任务：当天未使用就不联网。Python 3 标准库实现，不安装依赖。脚本缺失、Python 不可用或状态目录不可写时跳过并继续用户任务，不另行抓网页或自动安装工具。

## 持久状态

默认保存到 `~/.local/state/more-than-design-skill/update-checks.sqlite3`；设置 `XDG_STATE_HOME` 时改用该目录下的 `more-than-design-skill`。状态位于源码之外，不进入 Git 或分发包，Codex、Claude 和新对话使用同一用户状态。

按来源保存本地日期、带时区的检查时间、远端版本/提交、成功/失败状态。每日指执行机器本地时区的自然日，不是滚动 24 小时。不同渠道分别每天最多一次，因为 Git 提交和注册中心版本不能互相替代。不同操作系统用户/不同机器不共享；时区调整改变当地日期时可能触发新的日期检查。

SQLite 事务先占用当日检查，再联网。并发对话只允许一个发请求，其他读取缓存；失败当日也缓存。进程中断可能留下 `pending_or_interrupted`，当日不重试，次日首次使用再检查。连接超时有限，不储存原始错误输出或凭据。状态损坏时停止检查，不自动删除数据库来绕过限频。

## 渠道

- 本安装目录自身有 `.git`：识别 origin 中的个人或企业官方 GitHub 仓库，通过只读 `git ls-remote` 查看 main。支持 HTTPS 与常见 `git@github.com:` 地址；未知 origin 不联网。不会 fetch/pull，不写仓库。当前 HEAD 不同只标为 `remote_differs`，可能是本地领先、分叉或固定旧提交，后续需人工核对。另记录是否有本地改动。
- 无自身 `.git` 的 Skill Home/ZIP/复制包：用 `skill-home info @lukesong2000/more-than-design-skill --format json` 获取稳定版本，再与本地 manifest 比较。不解析私有安装缓存，也不假装能确定复制包来源。无 CLI 时保存不可用结果，不自动安装、不切换到其他来源。
- 符号链接按解析后的源码识别，不把宿主项目的 Git 仓库当 skill 来源。

检查只覆盖官方渠道的 main 提交与稳定三段版本；不检查预发布版本或任意 fork，也不检查 Apple/Google/Microsoft 文档是否更新。

## 输出和执行边界

`cached` 表示复用当天结果，`checked_at` 是实际尝试时间。`notify` 仅首次检查发现差异时为 true，后续对话不重复主动提醒。用户主动询问可读取缓存说明状态。更新本地文件后，会用本地当前版本重新比较已缓存的远端结果，不额外联网。

脚本从任意工作目录执行均可，例如 `python3 /实际安装路径/scripts/check_updates.py`。`--state-dir` 仅供隔离测试或管理员配置，不可每个对话换目录规避缓存。无需创建每日自动化；本机制不保证没有调用 skill 的日子也检查。

任何实际更新仍需用户授权；先保护本地改动和安装链接，再按渠道操作。不要用 `skill-home update` 当只读检查，它可能更新多项安装。旧版已安装 skill 不会凭空获得此能力，需要先取得含本脚本与入口指导的新版本。
